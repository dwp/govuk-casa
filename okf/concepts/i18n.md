CASA performs translations through dictionary files using the
[i18next](/references/i18next.md) library. On each request a `req.t()` function
is available in code, and a `t()` function is available in
[templates](/concepts/templating.md). Configure it through `i18n.dirs` and
`i18n.locales` in [`configure()`](/concepts/configure.md).

# Dictionary structure

Dictionaries live under one or more folders, each organised by locale then
file. Every file is a **namespace** and its entries are **keys**. YAML is
recommended over JSON for brevity and multiline support.

```text
/my-folder
  /en
    welcome.yaml
  /cy
    welcome.yaml
```

```yaml
# welcome.yaml
page_title: Hello, {{ salutation }}!
fields:
  name:
    label: What's your name?
```

# Using translations

```jinja
<h1>{{ t('welcome:page_title', { salutation: 'World' }) }}</h1>
<p class="govuk-body">{{ t('welcome:fields.name.label') }}</p>
```

This also shows i18next string interpolation (`{{ salutation }}`). The detected
language is stored in `session.language` and surfaced to templates as
`htmlLang`/`locale` by the data middleware (see the
[request lifecycle](/concepts/request-lifecycle.md)).

# Related

Validator [error messages](/concepts/validation.md) are typically i18n keys such
as `waypoint:field.name.error`.
