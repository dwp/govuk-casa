CASA uses i18next for translations. Each request receives `req.t()` and each
template receives `t()`.

# Dictionary shape

Dictionary directories are organised by locale. Files under each locale become
i18next namespaces.

```text
locales/
  en/
    common.json
    page.yaml
  cy/
    common.json
    page.yaml
```

# Configuration

`configure({ i18n: { dirs, locales } })` controls dictionary directories and
supported locales. CASA loads its bundled locales first, then user-supplied
directories so application dictionaries can override default strings.

# Relationships

Internationalisation is wired during [`configure()`](/concepts/configure.md)
and exposed during the [request lifecycle](/concepts/request-lifecycle.md).
It supports [Templating](/concepts/templating.md), validation messages, and
error pages.
